LLM 路由开启后切换模型不生效，帮我看看 initRouter 的 early-return

biran#1@biran-mac提问· 4 分钟前· 3 轮对话
biran#1@biran-mac提问· 4 分钟前
LLM 路由已经开着，我把 router.model 从 qwen 换成 never-stuck，cafe config get 显示新值，但 daemon 日志里没有重新初始化。是不是 initRouter 的 early-return 挡住了 llm → llm？
交给了
cafe#1@biran-mac Claude Code
为什么交给它：description 明确写了 router / 模型切换；唯一候选，没有调用模型。
cafe#1@biran-mac回答· 用时 35s

是。原来的分支是：

if (!model || this.router.name !== "rules") return;

它同时表达了“没配置”和“已经是 llm”两件事，所以只有 rules → llm 能发生。llm → llm 和 llm → rules 都被挡住。

修法是让 initRouter() 成为“按当前配置重建”：没有 model 就切回 RulesRouter；有 model 且和当前不同就重建；失败保留旧 router，并把错误返回给 /api/reload。

biran#1@biran-mac追问· 2 分钟前
那清空 router.model 呢？现在写空字符串好像也不会关闭 LLM。
cafe#1@biran-mac回答· 用时 12s

同一个 early-return 挡住。清空后应该显式换成 new RulesRouter()，并记录 router: rules；cafe router status 里 configured 和 running 都要显示 rules。

biran#1@biran-mac追问· 1 分钟前
如果新模型名字写错，配置会被写进去吗？
cafe#1@biran-mac回答· 用时 15s

现在 setAndApply() 会先写、再 reload，失败时把旧值写回，CLI 非 0 退出。Web 设置里也要走同一个接口，不要只写文件。
